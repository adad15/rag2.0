# M4.1 列举题召回补全与错片下压设计

- 日期：2026-06-17
- 类型：检索改进 spec（M4 baseline 驱动：列举题召回补全 + 错片下压）
- 分支：V3.2
- 状态：设计已确认（2026-06-17 brainstorm），待写实现计划
- 来源：M4 评估核心 [`2026-06-17-m4-retrieval-eval-core-design.md`](2026-06-17-m4-retrieval-eval-core-design.md) 跑出的 baseline + 对结果的数据分析；查询计划 spec [`2026-06-16-ragflow-lite-query-plan-design.md`](2026-06-16-ragflow-lite-query-plan-design.md) §6.2/§6.3
- 背景：M4 实测"哪些混凝土试验用到天平"在 k=20 的 `coverage@method_no = 12/23 (52%)`。分析候选集发现两类损失：① **8 个名额被假阳性占据**——"仪具与材料"章节但列的是压力机/万能机、并不含天平的 chunk；② **约 8 个真含天平的试验被埋得极深**，连 top-40 都进不来（天平在其章节里只是次要提及，BM25/dense 排名很低）。即"召回不全 + 精度不足"并存，且 §6.3 的 `method_no` 去重对本例无效（候选已是 20 个不同方法，无重复可去）。

---

## 1. 一句话目标

对"列举 + 命中关键词（如天平）"的查询：**先把库里所有正文含该关键词的片段一个不漏地召回（补全召回），再把不含关键词的片段统一下压（只重排不删除），最后截断 top_k**。把 `coverage` 从 52% 抬向接近满分（k 足够大时目标 ~23/23）。普通题 / 编号题完全不动。

---

## 2. 核心设计决策（已与用户确认）

### 2.1 召回补全：新增 PG 关键词直查路

新增 `PgClient::chunks_containing(keyword, status)`：`SELECT ... FROM retrieval_chunks rc JOIN standards s ON rc.standard_id=s.standard_id WHERE rc.embedding_text LIKE '%keyword%' AND s.status='现行'`，返回全部命中片段（`chunk_id`/`standard_id`）。

**为什么需要它**：BM25 是"按相关度排序"，会把"只顺带提一句天平"的片段排到很后甚至挤出 per_path_k 窗口（baseline 里 ~8 个真试验就是这么丢的）。直查只问"**有没有**关键词"——有就全收，**确定性、完备**。这正是 BM25/dense 给不了的补集能力，与 M3a 给方法号做的"PG 精确路"同思路，只是把精确匹配从"编号"扩到"内容关键词"。

`chunks_containing` 的结果有两个用途：(a) 作为一路候选进 RRF（把深埋片段拉进池子）；(b) 它返回的 `chunk_id` 集合 = "含关键词"的权威判定集，供 §2.2 下压直接用（无需对每个候选再回查正文）。

### 2.2 错片下压：在大池上按关键词命中稳定重排，再截断

> 关键点（否则白做）：只重排最终 top_k 没用——深埋的真片段本就不在那 top_k 里。下压必须在**截断前的大池**上做。

流程改为：先把各路（dense + bm25 + 关键词直查 + 方法号/条款号）**融合到一个足够大的池**（不提前截断到小 top_k），再做**稳定划分**：`chunk_id ∈ 关键词命中集` 的排前（组内保持 RRF 名次），其余排后，最后截断到调用方要的 top_k。新增纯函数 `demote_without_keyterms(fused, key_hit_ids, top_k)`，可单测；不改 `rrf_fuse` 本身（用大 top_k 调它即可，便于回滚）。

### 2.3 仅对 `ListByCondition` 且 `key_terms` 非空生效

与查询计划同一闸门：只有"识别为列举 + 命中仪器白名单"的查询才走召回补全 + 下压。其余意图（GeneralFact/MethodLookup/ClauseLookup）链路与现状完全一致 → 零回归。`key_terms` 来自现有 `build_query_plan`。

### 2.4 字段口径与状态过滤

直查与"是否含关键词"的判定**统一用 `embedding_text`**（含标题+正文+caption+公式，是 M2c-2 的受控语义文本），保证召回与下压口径一致。状态过滤 `status='现行'`，与 dense/bm25 路（`to_milvus_expr` 的默认 status）对齐；当前数据全为现行，对全现行库无害透传，M6 版本化后自然生效。

### 2.5 名额：列举题"答全"需 k ≥ 答案数

"哪些…"类问题答案天然是一组（天平有 23 个）。`coverage@k` 上限是 `min(k, gold 数)`——k=20 时顶天 20/23。故验证"答全"用更大的 k（如 `rag2 eval … 30`）。本刀**不**在 `text_retrieve` 内对列举题自动放大 k（避免悄悄改变返回条数的契约）；放大与否由调用方/评估按需控制。

## 3. 组件

| 文件 | 改动 |
|---|---|
| `src/db/pg_client.h` / `.cpp` | 新增 `chunks_containing(keyword, status)`（LIKE + standards join） |
| `src/retrieve/rrf.h` / `.cpp` | 新增纯函数 `demote_without_keyterms(fused, key_hit_ids, top_k)`（稳定划分 + 截断） |
| `src/retrieve/text_search.cpp` | `ListByCondition`+`key_terms` 时：调 `chunks_containing` 收集命中集与候选列表 → 融合到大池 → `demote_without_keyterms` → 截断 |
| `tests/test_rrf.cpp` | `demote_without_keyterms` 单测（含/不含/空命中集/截断/稳定性） |
| `eval/dataset_seed.json`（可选） | 维持天平覆盖用例；验证用 `rag2 eval … 30` |

`chunks_containing` 依赖真库，沿用项目惯例不单测，靠 `retrievecheck`/`eval` 实测验收；`demote_without_keyterms` 是纯函数，单测覆盖。

---

## 4. 数据流（仅列举+命中关键词时）

```text
build_query_plan → intent=ListByCondition, key_terms=[天平]
  ├─ dense.retrieve(dense_text)        （原有）
  ├─ bm25.retrieve(sparse_text)        （原有）
  ├─ 关键词直查：∪ pg.chunks_containing(t,现行) for t in key_terms  → key_hits 集 + 候选列表（新增）
  └─ 方法号/条款号路                    （原有，按需）
  → rrf_fuse(所有列表, k=60, top_k=大池)         // 不提前截断
  → demote_without_keyterms(fused, key_hits, top_k)  // 含天平的排前，其余下压，截断
```

非列举 / 无 key_terms：维持现状（`rrf_fuse(..., top_k)` 后按原逻辑返回）。

---

## 5. 不做（本刀边界）

- 不删除候选（只下压重排）。
- 不接 rerank 模型 / 学习型稀疏（spec §13 长期项）。
- 不在 `text_retrieve` 内对列举题自动放大 k（§2.5）。
- 不改 Milvus schema、不重建索引。
- 不改非列举意图的任何行为。
- 不做 `method_no` 去重（对本例无效，已论证）。

---

## 6. 验收标准

1. `rag2 eval eval/dataset_seed.json 30` 的天平用例 `coverage@30` 显著高于 baseline（目标接近 23/23；至少 ≥ 18/23）。
2. `retrievecheck "<天平列举题>" 30` top 段以"仪具与材料含天平"的不同试验为主，压力机/万能机等不含天平的仪具 chunk 退到后面。
3. 普通题（`路基沉降怎么评定`）、编号题（`T0302 需要哪些仪具`、`JTG…条款`）召回不回归——`rag2 eval` 点查指标不下降。
4. `demote_without_keyterms` 纯函数单测全过；全量 doctest 绿。
5. 不重建 collection、不改 Milvus schema。

---

## 7. 后续衔接

- 若召回补全后仍有 gold 进不了大池（理论上 LIKE 应已全收，除非该片段 `embedding_text` 里确无关键词字样），核查其 `embedding_text` 内容口径。
- 精度进一步提升（同义/近义、跨题型）留给 rerank 模型（spec §13）。
- 把更多列举题（不同关键词）纳入评估集，验证机制对天平以外的关键词同样有效。
