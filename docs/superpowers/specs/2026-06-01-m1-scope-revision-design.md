- 状态：已与项目负责人确认设计，待写实现计划
- 背景：M1 当初直接照计划执行、未走头脑风暴。代码已完成（Task 0–16）、单测 14 例全绿，但现场端到端验收未跑。本次复核发现两处"朴素实现"过脆/过假，且嵌入模型选型已落定，故做最小修订。

---

## 0. 复核结论（先说不变的）

**M1 的目标与五个接口契约全部不变**，不扩大范围：

- 目标：1 份原生 PDF → poppler 抽取 → 朴素条款切分 → 最小 PG 表 → 单路 dense 召回 → DeepSeek 带条款号溯源回答。
- 契约 ①Parser ②Embedding ③Retriever ④Candidate ⑤Context 一字不改。
- 底座原则不变：Milvus 只存向量 + node_id，原文以 PG 为权威，召回后用 `clause_id` 回查 PG。

本次只把朴素实现里**最脆**（条款切分，决定能否拿到端到端信号）和**最假**（standard_no=文件名 + 嵌入文本掺文件名）的地方补到"够用"，并落定嵌入模型。

## 1. 四项修订

### 修订① 嵌入文本只用条款正文

**问题**：现 [ingest_pipeline.cpp](../../../src/ingest/ingest_pipeline.cpp) 里
`retrieval_text = standard_no(=文件名) + " " + clause_no + " " + c.text`，
拼进了占位文件名（噪声）和条款号（对语义相似度近乎无用，且条款号精确匹配是 M3 的活）。

**改动**：dense 向量的输入文本改为**只用条款正文 `c.text`**（切分器已把条款号单独拆到 `clause_no`，正文不含号）。

**理由**：主设计文档 §7.2 的 `retrieval_text` 富化（标准号+名称+章节路径+正文+关键词+单位）思路正确，但前提是元数据为**真**。M1 暂无真元数据，故只嵌原文；M2 抽出真元数据后再升级为正规 retrieval_text，接口不变、无返工。

### 修订② 嵌入模型落定：Qwen3-Embedding-8B / 4096 维 / SiliconFlow

**背景**：路线图原把 Qwen3-Embedding-8B 列为 M5 才上的正式模型。实际 M1 即直接使用，经 SiliconFlow（OpenAI 兼容端点）调用。意味着 M1 的 embedding 已是正式模型，M5 的"换模型+灰度"可基本省去。

**改动**：纯配置，代码不动（[cloud_embedding.cpp](../../../src/embedding/cloud_embedding.cpp) 发的 `{"model","input":字符串}` 与解析 `data[0].embedding` 与 SiliconFlow 完全兼容）。更新 `.env.example` 默认值：

```
RAG_EMBED_BASE_URL=https://api.siliconflow.cn
RAG_EMBED_PATH=/v1/embeddings
RAG_EMBED_MODEL=Qwen/Qwen3-Embedding-8B
RAG_EMBED_DIM=4096
RAG_EMBED_KEY=<SiliconFlow key>
```

**注意**：Milvus `clause_text` 集合按 `embed.dim()` 建，env 设 4096 即自动建 4096 维；**若此前已用 1024 维建过该集合，需先删除重建**。

### 修订③ 切分器加固（[clause_splitter.cpp](../../../src/ingest/clause_splitter.cpp)，仍为纯函数、走 TDD）

朴素切分仍是 M1 的一次性实现（M2 由条款层级树正规替换），但需稳到"能稳定点火"。三条：

- **必做 — 全角归一化**：正则匹配前，把行内**全角空格 `　`(U+3000) → 半角空格、全角数字 `０-９`(U+FF10–FF19) → 半角数字、全角句点 `．`(U+FF0E) → `.`**。这是消灭 `clauses=0`（国标常用全角空格分隔条款号与正文，`std::regex` 的 `\s` 不认全角空格）的关键。
- **应做 — 支持到四级**：条款号正则放宽到 2~4 级（`4.2` / `4.2.1` / `4.2.1.1` 均收，保留 `-x` 后缀），避免四级条款被整条丢弃。
- **明确跳过 — 单级章标题**（如"4 桥涵设计"）：M1 **不**识别单级编号开头。理由：单数字开头误判率高（表格行"2 100 200"、列表"3 个螺栓"会被误当条款）；验收要引用的是 `4.2.1` 这类多级号，单级标题对验收无用。章标题正文被并入相邻条款，M1 可接受。

**未解决（M1 接受）**：poppler 排版导致的换行错位（条款号与正文分行、多条挤一行、双栏交错）不在 M1 处理范围，靠选一份排版规整的原生 PDF 规避；M2 用 MinerU + 层级树根治。

### 修订④ standard_no 轻量抽取（新增纯函数、走 TDD）

**问题**：现入库用文件名顶替 standard_no / standard_name。修订①之后文件名已不再进向量，故该占位**仅影响回答里打印出来的标准号**（外观问题，不影响召回与验收）。但标准号易抽，顺手做真。

**改动**：新增一个纯函数，对**首页文本**用正则找标准号——模式形如 `[A-Z]{2,}(/[A-Z]+)?\s*\d+(\.\d+)?-\d{4}`（覆盖 `JTG D60-2015`、`GB 50010-2010`、`GB/T 50081-2019`、`JGJ 3-2010` 等）。

- 找到 → standard_no 用真号；找不到 → 回退文件名。
- `standard_name`：M1 仍用**文件名（去扩展名）**；从正文可靠抽中文标准名需字号信息，poppler 无，留给 M2。

**影响**：回答里标准号能变真（首页含标准号时）；标准名暂仍为文件名。M2 做正经元数据抽取时只替换 standards 表列值的来源，**不动 schema、不动接口，零返工**。

| 修订 | 改的位置 | 改动量 | 接口/Schema 影响 |

五个契约、PG schema、Milvus schema、子命令接口**全部不变**。

## 3. 修订后的 M1 验收

不变的硬判据：

1. `rag2 ingest`（用一份排版规整的原生 PDF、SiliconFlow 4096 维 embedding）写入 **N>0** 条条款；切分数量与文档条款规模大致相称（不再因全角空格等出现 `clauses=0`）。
2. `rag2 query "<该 PDF 中某条款相关问题>"` 返回回答，且**引用到该文档真实存在的条款号**（与 PG `clause_no` 对得上）。

修订带来的可观察改善：

- 回答里的**标准号**在首页含标准号时为真（修订④）。
- 嵌入向量不含文件名噪声（修订①）、使用正式 Qwen3-8B（修订②），召回更靠谱。

## 4. 测试策略
