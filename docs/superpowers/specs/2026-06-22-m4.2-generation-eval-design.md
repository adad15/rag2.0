# M4.2 生成侧评估（条款引用 + 数值准确率）设计

- 日期：2026-06-22
- 类型：评估扩展 spec（M4 后半段：生成侧指标，只测量、不改生成逻辑）
- 分支：V3.3
- 状态：设计已确认（2026-06-22 brainstorm），待写实现计划
- 来源：M4 评估核心 [`2026-06-17-m4-retrieval-eval-core-design.md`](2026-06-17-m4-retrieval-eval-core-design.md) §2.1/§8 明确留出的“M4 后半段（生成侧）”；当前 eval 仅测检索（[`src/eval/eval_runner.cpp`](../../../src/eval/eval_runner.cpp) 只调 `text_retrieve`，从不调 `answer_query`）。
- 背景：现有 eval 只回答“对的 chunk 有没有被召回”（coverage / hit@k / MRR），完全不验证模型最终吐出的那段答案。但 [`src/generate/prompt_builder.cpp`](../../../src/generate/prompt_builder.cpp) 的 system prompt 对模型立了 6 条军令（只依据上下文、必须标标准号+条款号、强制性/废止提示、不足必须拒答、不得编造条款号/限值/单位），目前零自动化验证。召回 100% 正确也不代表答案把“T0316 压力机精度”答对、不代表没编造一个不存在的条款号。本刀把评估从“检索层”延伸到“用户真正读到的答案层”。

---

## 1. 一句话目标

给 `rag2 eval` 加一个 opt-in 的 `--gen` 开关：对带生成 gold 的用例，调 `answer_query` 拿到答案文本，自动打两个纯测量指标——**条款引用准确率**（答案有没有引对标准号+条款号/方法号）和**数值准确率**（答案有没有给对限值/单位）。带答案磁盘缓存保证可复现。不改任何生成/检索逻辑，只测量。

---

## 2. 范围（已与用户确认）

**做：**
- `rag2 eval <dataset> [k] [planner] [--gen]`，`--gen` opt-in 才跑生成（默认不烧 token）。
- 两个指标：条款引用准确率、数值准确率。
- 共用现有数据集文件、合并报告（检索段 + 生成段）。
- 答案磁盘缓存（可复现、重跑免费）。
- `gold_values`（数值题期望的限值/单位）由实现者从 `data/chunk_cache/*.json` 真相源导出（~10-15 条数值题），用户抽查；引用准确率复用现有 5 条点查/条款用例的 gold，不另标注。

**不做（YAGNI / 留后续）：**
- 拒答正确性指标（撤出本 spec）。
- 数值幻觉测量/硬拦截（§11.4 硬拦截，需 `answer_query` 暴露 context，留 Phase C）。
- 拒答阈值标定。
- LLM-judge 语义裁判。
- 评估集扩到 ~100（领域人员后续按 M4 核心 §15.5 流程做）。
- 改 `answer_query` 签名、改检索/生成逻辑。

---

## 3. 核心架构决策

### 3.1 非侵入：通过缓存包装复用现成 `answer_query`（方案 A）

新增 `run_generation_eval` 编排函数，对每条 gen 用例通过一个缓存包装调用现成的 `answer_query`，**不动 `answer_query` 签名**。

- **答案缓存键** = `hash(normalize_question(question) + "\x1f" + prompt_version)`，磁盘缓存目录 `data/answer_cache`，复用 query_plan_cache 的实现套路（归一化键、写失败非致命、有效产物才缓存）。
- **已知限制（写入文档纪律）**：缓存键**不绑检索上下文**。若改了检索/RRF/query plan，跑生成 eval 前需手动清 `data/answer_cache` 强制重算（与 query_plan_cache 改 prompt 要 bump version 同属缓存纪律）。
- **双次检索**：`--gen` 时每条 gen 题会检索两次（一次在 `run_eval` 算检索指标、一次在 `answer_query` 内部）。eval 规模（~20 条）下可忽略，换来 `answer_query` 零改动。

**为什么不选方案 B（改 `answer_query` 返回 `{answer, fragments}`，缓存绑上下文、单次检索）**：本 spec 两个指标都只需答案文本、不需要 context；为零收益改生产签名不值。方案 B 留到做数值幻觉拦截（Phase C，本就需要 context）时再上。

### 3.2 prompt_version 常量

为答案缓存键引入 `kAnswerPromptVersion`（如 `"ans-v1"`），与 `build_system_prompt` 配套。改 system prompt 必须同步 bump 它，使旧缓存自动失效。

## 4. 组件（小而专，各自可独立测）

### 4.1 数据集：`EvalCase` 加 `gold_values`

[`src/eval/dataset.h`](../../../src/eval/dataset.h) 的 `EvalCase` 加：
```cpp
std::vector<std::string> gold_values;   // 数值题期望出现的限值/单位（空=非数值题）
```
`parse_dataset` 读 `gold_values` 字符串数组，缺字段取空。引用相关字段（`gold_standard_no`/`gold_clause_no`/`gold_method_no`）已存在，复用。

### 4.2 纯指标：`src/eval/generation_metrics.{h,cpp}`（全量 TDD）

```cpp
// 归一化：去空格、全角数字→半角、ASCII 转小写。纯函数。
std::string normalize_for_match(const std::string& s);

// 引用命中：归一化后答案同时包含 标准号 与 条款号/方法号 → true。
// gold_ref 传 method_no 或 clause_no（取该用例非空者）。
bool citation_hit(const std::string& answer,
                  const std::string& gold_standard_code,
                  const std::string& gold_ref);

// 数值命中数：归一化后 gold_values 里有几个出现在答案中。
int count_value_hits(const std::string& answer,
                     const std::vector<std::string>& gold_values);
```

- `citation_hit` 要求**双含**（标准号 + 条款/方法号），对应 prompt 军令②。两者任一缺则不命中。
- `normalize_for_match` 处理全角数字是因为 OCR/标准原文常见全角“１％”，模型也可能回全角。
- 这三个是纯字符串/数字处理，**完整 red-green TDD**：归一化用例、引用“双含/缺标准号/缺编号”、数值“全中/部分中/全角等价/空 gold”。

### 4.3 编排：`src/eval/generation_eval.{h,cpp}`

```cpp
struct GenCaseResult {
    std::string question;
    bool cite_scored = false;  bool cite_hit = false;
    int value_gold = 0;        int value_hits = 0;   // value_gold==0 表示非数值题
};
struct GenerationReport {
    int cite_scored = 0,  cite_hits = 0;
    int value_gold_total = 0, value_hit_total = 0;
    std::vector<GenCaseResult> results;
};

GenerationReport run_generation_eval(
    const std::vector<EvalCase>& cases,
    milvus::MilvusRest& mv, EmbeddingClient& embed, PgClient& pg,
    const SynonymDict& syn, deepseek::DeepSeekClient& ds,
    const std::string& collection, int top_k,
    const QueryPlanner& planner, const std::string& answer_cache_dir);
```

每条用例：
1. 选 gold_ref：`gold_method_no` 非空取它；否则 `gold_clause_no` 非空且 `gold_standard_no` 非空取条款号（标准号解析见下）。两者皆无 → 不打引用分。
2. 若有引用 gold 或 `gold_values` 非空 → 取缓存答案（缓存未命中则调 `answer_query` 并缓存）；否则跳过本条（不调 LLM）。
3. 有引用 gold → `citation_hit` 累加 `cite_scored`/`cite_hits`。
4. `gold_values` 非空 → `count_value_hits` 累加 `value_gold_total`/`value_hit_total`。
5. 单条 `answer_query` 抛异常 → `spdlog::warn` 并该条不计分，继续。

内部含答案磁盘缓存助手（与 query_planner 缓存同形）。`gold_standard_no` 形如 “JTG 3420” 时复用 eval_runner 已有的去空格 + `find_standard_by_code` 思路得到标准号文本（引用匹配用的是**标准号文本**如 `JTG3420`，不是内部 standard_id）。

### 4.4 接线：`src/main.cpp` `cmd_eval`

- 派发块解析 `--gen`（出现在任意位置即置位；k 和 planner 仍按位置解析，跳过 `--gen` token）。
- `--gen` 时：构造 `ds`（已有 DeepSeekClient），先打印现有检索报告，再调 `run_generation_eval` 打印生成段。
- 缺 DeepSeek key → `--gen` 提前报错退出（复用 `missing_required`，与 cmd_query 一致）。
- 不带 `--gen` → 行为与现状完全一致。

### 4.5 工程登记

`rag2.0.vcxproj`(+`.filters`) 加 `generation_metrics.{h,cpp}`、`generation_eval.{h,cpp}`；`rag2.0.tests.vcxproj`(+`.filters`) 加 `generation_metrics.cpp` + `test_generation_metrics.cpp`（编排层 infra-bound 不进测试工程的被测单测，仅纯指标进）。

## 5. 数据流（每条 --gen 题）

```
question
  ├─（检索指标，走现有 run_eval / text_retrieve，不变）
  └─ 缓存包装(answer_query) → 答案串
        ├─ citation_hit(answer, 标准号, 方法号/条款号)        → cite
        └─ count_value_hits(answer, gold_values)              → num
                                                              → GenerationReport
```

---

## 6. 报告形态（合并）

```
[检索段：保持现状——coverage / point hit@k / MRR]

--- 生成侧（--gen）---
[cite] ✓  T0521 水泥混凝土拌合物拌和与现场取样需要哪些仪具
[cite] ✗  T0316 需要哪些仪具
[num ] 2/2  某沥青针入度数值题
引用准确率: 4/5    数值准确率(逐值): 18/22
```

逐值口径：`value_hit_total / value_gold_total`（跨所有数值题累加，比“整题全中率”更细粒度地暴露错在哪几个值）。

---

## 7. 错误处理

- 单条 DeepSeek 调用失败 → warn + 该条不计分，不中断全量。
- 缺 DeepSeek key（`--gen`）→ 提前报错退出。
- 答案缓存写失败 → 非致命，下次重算。
- `gold_clause_no` 非空但 `gold_standard_no` 空 / 标准未找到 → 该条引用不计分并 warn（沿用 eval_runner 现有口径）。

## 8. 测试策略

- **纯指标（`generation_metrics`）**：完整 red-green TDD。覆盖 `normalize_for_match`（去空格/全角→半角/ASCII 小写）、`citation_hit`（双含命中 / 缺标准号 / 缺编号 / 空串）、`count_value_hits`（全中 / 部分 / 全角等价 / 空 gold）。
- **dataset parse**：`gold_values` 有/无两用例。
- **`run_generation_eval` 编排层**：infra-bound（依赖 Milvus/PG/DeepSeek），不单测，与现有 `run_eval` 一致——靠 `rag2 eval eval/dataset_seed.json 30 --gen` 实跑种子集 + 人工抽查报告验证。

---

## 9. 验收

1. 全量单测绿（含新纯指标用例）。
2. `eval --gen` 在扩充后的种子集上跑通，打印检索段 + 生成段。
3. 引用准确率：5 条点查/条款用例中，答案确实引出标准号+编号的判为命中；人工抽查 2 条确认判定正确（无假阳/假阴）。
4. 数值准确率：~10-15 条数值题的 `gold_values` 由实现者从 chunk_cache 导出、用户抽查无误；逐值命中率与人工核对一致。
5. 重跑同命令，指标**逐字一致**（答案缓存生效）。
